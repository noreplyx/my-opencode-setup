5 · Code

Code you can copy and run

Read the story first: the old snippet fetched blindly, while the new snippet validates and retries safely. Identifiers stay English; the prose around them is bilingual.

new code · TypeScriptsrc/REPLACE-THIS-path.ts
// REPLACE-THIS new behavior. Keep identifiers English.
async function loadOrderSafe(orderId, client) {
  const res = await client.get("/api/orders/" + orderId, { timeoutMs: 2000 });
  if (!res.ok) throw new Error("order-load-failed:" + res.status);
  return res.json();
}

6 · Runtime

How it works at runtime

Follow these five numbered steps in order. Each step names the actor first, then the action, so the handoff stays visible.

  1. The client sends POST /orders with an idempotency key in the header.
  2. The API validates the shape and returns 400 with field errors when invalid.
  3. The service checks the key, then writes once to the store.
  4. The store confirms, and the service builds a receipt.
  5. The API returns 201 with the receipt, and duplicates replay it safely.

Store slowdown cascades.Queues grow and latency spikes quickly.We bound waits and shed load with 503 plus Retry-After.
Can we adopt this incrementally without a rewrite?

Yes, you can wrap one endpoint first because the new client falls back to the old path. That lets you measure before widening the rollout.

What should we log to debug this in production?

Log the idempotency key, the decision branch, and the store duration on every write. Those three fields explain nearly every incident.

When it breaks, look here first

Common symptoms, causes, and fixes.
SymptomLikely causeFix
Duplicate orders appear twice.The idempotency key is missing or regenerated per retry.Send one stable key per order in the request header.
Requests fail with 400 field errors.The payload shape changed without updating validation.Open the API validator and align the schema with the client.
Pitfall: retry storms hide the real error.

The client retries too fast and floods the logs, so the first failure scrolls away. Back off exponentially and log the idempotency key once per attempt.
